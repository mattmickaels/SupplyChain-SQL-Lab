Kestrel builds the specialized equipment that semiconductor manufacturers use to make and inspect chips. Its finished products are called tools: complex machines assembled from modules, which in turn contain purchased components. Kestrel also sells spare parts to support equipment already in use.

01 / THE BIG PICTURE

A database stores data. SQL asks questions.

A database is an organized collection of data. A database engine is the software that stores it, applies rules, and answers queries. This lab uses an engine called DuckDB.

  1. ▦Tables store factsSuppliers, orders, and order items each have a place.
  2. ?A query asks a question“Which items belong to this purchase order?”
  3. ≡The engine returns rowsA result contains the columns and rows requested.
  4. ▣A screen presents themThe application arranges the result into fields and grids.

SQL is a language for expressing those questions. A SELECT query reads data; it does not change the stored rows. Other SQL commands can change data, but this lab's lessons are read-only.

If you know Excel: a table resembles a named sheet with column headers. A database adds explicit data types, keys, and rules for connecting records. You do not need Excel experience to continue.

A NULL represents a missing or unknown value. It is different from zero or an empty text string. Also, stored rows have no guaranteed display order; SQL uses ORDER BY when order matters.

03 / CONNECTING TABLES

Related tables share identifiers.

A relational database organizes data into tables that can be connected through matching values. A foreign key (FK) refers to a key in another table. These links let us keep a supplier's details in one place and reuse its identifier on many orders.

Sometimes the key is a pair

In purchase_order_item, the primary key is po_no + line_no together. PO-0006693 repeats for each item, and item 1 can appear on other orders. Only the pair identifies a particular item.

Why separate the tables?

Copying a supplier's name and address onto every item would repeat data and invite conflicting updates. A supplier table stores those facts once. A JOIN brings related facts together when we need them.

The PK/FK labels describe each column's role; the highlights show equal values used to connect these example rows. The lab models these relationships, but does not enforce every foreign-key rule in its generated database.

Check your understanding: is line_no enough to identify one order item?

No. Different orders can both have item 1. You need the PO number and item number together.

What happens when an order has three items?

The purchase_order table still has one header row for that order. The purchase_order_item table has three rows with that PO number. Joining the header to the items produces three matching pairs.

A screen layout is not the database structure. The application can show names from lookup tables, calculate quantities, and display only part of a result. A JOIN connects matching records; it does not permanently merge the stored tables.

A schema describes the structure: tables, column names, types, and keys. Use the lab's Schema page as your data dictionary. A view is a named query you can read like a table; the lab also includes views with SAP-style field names.

Your first database vocabulary

Database
An organized collection of stored data.
Table
Rows of the same kind of record, with named columns.
Primary key
One or more columns that uniquely identify a row; primary-key values cannot be NULL.
Foreign key
A reference from a row to a key in another table. When enforced, it prevents references to missing records.
Query / result
A request for data, and the rows returned in response.
JOIN
A way to combine matching rows from tables in a query.
